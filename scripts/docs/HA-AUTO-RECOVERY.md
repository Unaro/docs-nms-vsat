# Сохранение расходящейся ветки и восстановление реплики

## Гарантии и границы

`pgsqlms-ha` — обёртка PAF. Fencing/quorum в этой доработке не изменяются.
Без внешнего подтверждения единственного авторитетного primary автоматический
выбор источника при split-brain не гарантируется. Проверки writable-состояния и
system_identifier защищают от ряда ошибок, но не заменяют эту гарантию.

Различайте три задачи:

1. **Сохранить исходную расходящуюся ветку.** До первого изменения PGDATA
   создаётся физический архив остановленного экземпляра, включая доступный WAL.
2. **Вернуть узел в физическую репликацию.** pg_rewind, при ошибке — pg_basebackup.
3. **Объединить расходящиеся изменения.** Автоматически не выполняется.
   Это отдельная задача анализа и разрешения бизнес-конфликтов.

Архив не гарантирует доступность уже удалённого WAL или исправность исходных
данных. SHA-256 подтверждает неизменность копии, а не логическую целостность БД.
Локальный архив не защищает от потери диска/узла: для такой гарантии обязательна
проверенная копия на независимом хранилище до разрешения перезаписи.

## Реализовано

- PAF остаётся ответственным за штатные start/stop/promote/demote/notify.
- Неизвестные hostname, несовпадающие параметры OCF, небезопасные пути и таймауты
  отклоняются. Конфигурация должна принадлежать root и не быть доступной на запись
  группе/остальным, поскольку она исполняется через source.
- meta-data не изменяет PGDATA и не требует локального конфигурационного файла.
- start проверяет, что экземпляр ещё не запущен; повторный start не перестраивает
  работающий primary/standby.
- Источник выбирается через SQL по Ring0, затем Ring1, и фиксируется на время
  восстановления. Проверяются writable-состояние и идентификатор кластера.
- После подтверждённой остановки выполняются tar, tar --compare, SHA-256 и sync.
  Только затем появляется файл COMPLETE. При ошибке архивирования восстановление
  останавливается; частичные архивы сохраняются для диагностики.
- Любые symlink в исходном PGDATA блокируют автоматическое восстановление.
  Это намеренное ограничение для внешнего WAL/tablespaces. Внешние tablespaces
  источника также отклоняются, чтобы plain basebackup не писал в исходные пути.
- pg_rewind и pg_basebackup запускаются настоящими программами под timeout.
- Basebackup использует уникальный staging-каталог. Каждый перенос проверяется;
  при ошибке установки предпринимается откат. Прежний каталог и архив не удаляются.
  Два rename не являются одной атомарной транзакцией.
- Восстанавливаются локальные primary_conninfo с Ring0/Ring1 и primary_slot_name.
  Прочие настройки postgresql.auto.conf сохраняются.
- Флаг need_resync снимается после обнаружения streaming, не после скачивания.
- SELinux/AppArmor автоматически не отключаются.

## Почему удалён автоматический SQL-экспорт

pg_waldump показывает физические записи WAL, а не исходные SQL-команды.
Поиск сохранившихся строк по xmin не восстанавливает DELETE, историю UPDATE,
полный порядок/границы транзакций, DDL, последовательности и все subtransaction.
track_commit_timestamp добавляет время коммита, но не историю данных.
Предыдущая реализация также отбрасывала RAISE NOTICE через stderr.
Ненадёжный экспорт и запуск изменяемого исходного PGDATA в изолированном режиме
удалены. Вместо них сохраняется исходная физическая ветка.

Для анализа извлеките архив в НОВЫЙ изолированный каталог, проверьте SHA256SUMS,
используйте соответствующую major-версию PostgreSQL, запретите исходящие соединения
и приложения. Оригинальный архив не изменяйте. Дальнейшее логическое сравнение
таблиц и перенос выполняются по базам, с анализом конфликтов. Это пока ручной этап.

## Параметры /etc/default/ha-cluster

```bash
GRACE_PERIOD_SEC=30
TAIL_BACKUP_TIMEOUT_SEC=900
REWIND_TIMEOUT_SEC=180
BASEBACKUP_TIMEOUT_SEC=540
PG_STOP_TIMEOUT_SEC=60
SQL_TIMEOUT_SEC=3
# Необязательное отдельное хранилище вне PGDATA:
RESCUE_DIR=/var/lib/postgresql/tail_backups
```

COLD_START_TIMEOUT_SEC остаётся параметром холодного старта/quorum и не задаёт
таймаут basebackup. При изменении бюджетов нужно обновить и операцию start в CIB.
configure-ha.sh рассчитывает её как сумму архивирования, rewind, basebackup,
остановки и 180 секунд запаса. Для больших БД бюджеты подбираются испытаниями.

## Хранение

Архивы: `RESCUE_DIR/branch_HOST_TIMESTAMP_RANDOM/pgdata.tar`.
Рядом: SHA256SUMS, COMPLETE и backup.log. Незавершённый архив без COMPLETE
не разрешает восстановление. Лог: RESCUE_DIR/tail_recovery.log.
Каталоги имеют права 0700 и принадлежат root; архивы содержат чувствительные данные.
Автоматической ротации нет: обязательны мониторинг свободного места, квоты,
внешнее резервирование, шифрование и согласованный срок хранения.

## Что ещё необходимо

- Интеграционные испытания на целевой версии PostgreSQL/PAF/Pacemaker.
- Проверенная внешняя копия/снимок, если требуется пережить потерю диска.
- Поддержка согласованных snapshot внешнего WAL и tablespaces с отображением путей.
- Crash-safe журнал смены PGDATA для автоматического завершения/отката после
  отключения питания между rename. Пока при таком сбое может требоваться оператор.
- Отдельная проверка успешного запуска и устойчивого streaming с alerting.
- Инструменты логического сравнения восстановленной архивной ветки и primary.
- Проверка авторитетности primary на уровне кластера (вне этой доработки).

## Проверки

```bash
python3 tests/test-pgsqlms-ha.py
sudo ./validate-pgsqlms-ha.sh
```

Локальные тесты проверяют архив/контрольную сумму/восстановление файлов,
отказ при symlink, отказ при ошибке копирования, сохранение auto.conf и bash -n.
Они НЕ проверяют реальное PostgreSQL/Pacemaker-восстановление.
На одноразовом стенде дополнительно нужны: отказ rewind, потеря WAL, таймаут,
нехватка места, read-only filesystem, прерывание rename, рестарт узла, оба кольца,
идемпотентный start и недоступность источника. Не удаляйте рабочий pg_wal вручную.
