# FAQ

**Сохраняется ли полный SQL-хвост?** Нет. Сохраняется физическая копия исходной
ветки. pg_waldump + xmin не восстанавливают полную историю операций.

**Слияние автоматическое?** Нет. Требуется отдельный анализ ветки из копии и
разрешение конфликтов. Не применяйте общий SQL-файл ко всем базам.

**Что происходит при ошибке архива?** Перезапись запрещена. Частичный архив остаётся
для диагностики и не получает COMPLETE.

**Что происходит при ошибке basebackup?** Возвращается ошибка OCF, staging остаётся.
Исходная ветка сохранена в проверенном архиве; сам рабочий PGDATA уже мог быть
изменён неудачным pg_rewind.

**Можно удалить старые архивы автоматически?** В этой версии нет. Нужны политика
хранения и подтверждённое внешнее резервирование. Контролируйте свободное место.

**Защита от потери диска?** Только при независимой внешней копии, не локальным tar.

**Внешний WAL/tablespaces?** Автоматическое восстановление блокируется до реализации
согласованных снимков и безопасного отображения путей.

**Команды диагностики**

```bash
pcs status
journalctl -t pgsqlms-ha
sudo tail /var/lib/postgresql/tail_backups/tail_recovery.log
python3 tests/test-pgsqlms-ha.py
```

Для проверки архива: в его каталоге выполните `sha256sum -c SHA256SUMS`.
Не используйте pg_archivecleanup на рабочем pg_wal и не выбирайте primary по
сравнению числового LSN разных таймлайнов.
