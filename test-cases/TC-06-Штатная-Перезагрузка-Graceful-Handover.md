# TC-06: Штатная перезагрузка узла (Graceful Handover)

## 1. Паспорт тест-кейса
- **Идентификатор**: `TC-06`
- **MMD-диаграмма**: [`mmd/ПлановоеВыключениеКластера.mmd`](../mmd/ПлановоеВыключениеКластера.mmd)
- **Цель**: Проверить процедуру плановой передачи обслуживания при штатной перезагрузке активного Master-узла (`node1`), фиксацию роли перехватчиком `cluster-shutdown-marker`, бесшовный перехват нагрузки вторым узлом (`node2`) и возврат `node1` после перезагрузки строго в роли `Slave` (без паразитного перехвата роли).
- **Объекты проверки**:
  - Юнит `cluster-shutdown-marker.service` и скрипт `/usr/local/sbin/cluster-mark-shutdown.sh`.
  - Запись маркера `LAST_KNOWN_ROLE=MASTER` в `/var/lib/cluster-state/graceful_shutdown`.
  - Передача роли Master на `node2`.
  - Стабильность правила `resource-stickiness=100`.

---

## 2. Предусловия
1. Кластер находится в штатном состоянии (`TC-01`), `node1` — Master, `node2` — Standby.
2. Сервис `cluster-shutdown-marker.service` активен на обоих серверах.

---

## 3. Шаги выполнения и ожидаемые результаты

### Шаг 1. Инициирование штатной перезагрузки node1
**Команда на `node1`:**
```bash
systemctl reboot
```

---

### Шаг 2. Контроль перехвата нагрузки на node2 в процессе остановки node1
**Команда на `node2`:**
```bash
pcs status
```
**Ожидаемый результат:**
- `node1` переходит в статус `standby` / `offline`.
- Pacemaker на `node2` промоутирует СУБД в `Master`.
- Ресурсы `vip`, `core-app-stack` и `daemon-svc` запускаются на `node2`.
- Прерывание обслуживания клиентов минимизировано (не более 3–5 секунд на миграцию VIP).

---

### Шаг 3. Возврат node1 в строй после перезагрузки (Rejoin)
**Команда на `node1` (после завершения загрузки ОС):**
```bash
pcs status
```
**Ожидаемый результат:**
- `node1` успешно загрузился, Corosync собрал два кольца.
- **Критический результат**: СУБД на `node1` стартует как `Unpromoted` (Slave / Standby) и начинает принимать репликацию от `node2`.
- `node2` **остается активным Master**, VIP и сервисы продолжают работать на `node2` без обратного дергания (благодаря `resource-stickiness=100`).

---

## 4. Восстановление исходного состояния
```bash
# При необходимости вернуть роль Master на node1:
pcs resource move vip node1
pcs resource clear vip
```

---

## 5. Что делать при отклонении
1. Если при выключении `node1` на диске не был сохранен маркер:
   - Проверить статус службы:
     ```bash
     systemctl status cluster-shutdown-marker.service
     ```
   - Проверить права на каталог состояния:
     ```bash
     ls -ld /var/lib/cluster-state
     # Должно быть: drwx------ root root
     ```
2. Если `node1` после ребута пытается стать Master одновременно с `node2`:
   - Проверить наличие `standby.signal` в `$PGDATA` и журнала анализатора:
     ```bash
     journalctl -u cluster-boot-analyzer -n 30 --no-pager
     ```
