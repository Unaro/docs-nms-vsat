# TC-03: Сбой сервиса приложения или демона на узле с VIP

## 1. Паспорт тест-кейса
- **Идентификатор**: `TC-03`
- **MMD-диаграмма**: [`mmd/ПадениеApp1.mmd`](../mmd/ПадениеApp1.mmd)
- **Цель**: Проверить устойчивость кластера к локальному сбою сервисов приложения с валидацией развязки судьбы ресурсов (Fate-Sharing) версии 4.0:
  1. При отказе основного приложения `my-app` группа `core-app-stack` и VIP мигрируют на `node2`, а зависимый `daemon-svc` следует за ними.
  2. При отказе второстепенного демона `my-daemon` группа `core-app-stack` и VIP **НЕ перезапускаются и НЕ мигрируют**, продолжая обслуживать клиентов на `node1`.
  3. Сохранение роли Master за СУБД на `node1` и маршрутизация трафика через Ring 0.
- **Объекты проверки**:
  - Группа `core-app-stack` (`haproxy-svc` + `app-svc`).
  - Односторонняя зависимость: `order start core-app-stack then start daemon-svc symmetrical=false`.
  - Colocation: `core-app-stack with vip INFINITY` и `daemon-svc with core-app-stack INFINITY`.
  - Маршрутизация HAProxy через прямое соединение Ring 0 (`10.0.0.1:5432`).

---

## 2. Предусловия
1. Кластер находится в штатном режиме (`node1` — Master БД, VIP, `core-app-stack` и `daemon-svc` активны на `node1`).
2. Сетевое кольцо Ring 0 (`10.0.0.1` <-> `10.0.0.2`) исправно.
3. Сервисы `my-app` и `my-daemon` запущены.

---

## 3. Шаги выполнения: Сценарий А (Сбой второстепенного демона — проверка Fate-Sharing)

### Шаг А1. Имитация аварии my-daemon на node1
**Команда на `node1`:**
```bash
pkill -9 -e -f "my-daemon"
```

### Шаг А2. Контроль сохранения работы ядра NMS
**Команда на `node1`:**
```bash
pcs status
```
**Ожидаемый результат:**
- `core-app-stack` (`vip`, `haproxy-svc`, `app-svc`) **ПРОДОЛЖАЕТ РАБОТАТЬ НА `node1`**!
- Никакой миграции VIP на `node2` не произошло.
- Pacemaker пытается перезапустить только сбойный `daemon-svc` на месте. Клиенты NMS не заметили сбоя.
- Восстановление: `pcs resource cleanup daemon-svc`.

---

## 4. Шаги выполнения: Сценарий Б (Сбой основного приложения my-app)

### Шаг Б1. Имитация аварии my-app на node1
**Команда на `node1`:**
```bash
pkill -9 -e -f "my-app"
```

### Шаг Б2. Контроль миграции ядра и зависимого демона на node2
**Команда на `node1` / `node2`:**
```bash
journalctl -u pacemaker -f --no-tail
```
**Ожидаемый результат:**
1. Pacemaker фиксирует сбой `app-svc`:
   `app-svc_monitor_10000 on node1 'not running' (7)`
2. Pacemaker останавливает зависимый `daemon-svc` на `node1`.
3. Pacemaker останавливает `core-app-stack` и снимает `vip` с `node1`.
4. Pacemaker поднимает стек на `node2`:
   - запуск `vip`
   - запуск `core-app-stack` (`haproxy-svc`, `app-svc`)
   - запуск зависимого `daemon-svc`

### Шаг Б3. Проверка статуса ресурсов и ролей СУБД
**Команда на любом узле:**
```bash
pcs status
```
**Ожидаемый результат:**
- `Clone Set: pgsql-clone`:
  - `Promoted: node1` (Master остался на `node1`!).
  - `Unpromoted: node2` (Standby остался на `node2`!).
- `Resource Group: core-app-stack`:
  - `vip`: Started `node2`.
  - `haproxy-svc`: Started `node2`.
  - `app-svc`: Started `node2`.
- `daemon-svc`: Started `node2`.

### Шаг Б4. Проверка сквозной передачи SQL-трафика через HAProxy2 на Master node1
**Команда на `node2`:**
```bash
psql -h 127.0.0.1 -p 5000 -U haproxy_check -d postgres -c "SELECT inet_server_addr(), pg_is_in_recovery();"
```
**Ожидаемый результат:**
- Запрос выполнен успешно.
- `inet_server_addr` показывает `10.0.0.1` (балансировщик `node2` отправил запрос по прямому линку на Master СУБД узла `node1`).
- `pg_is_in_recovery` равно `f` (транзакции записи доступны).

---

## 5. Восстановление исходного состояния (Teardown)
```bash
pcs resource cleanup app-svc
pcs status
```

---

## 6. Критерии успешности (Pass/Fail)
- **PASS**:
  - При падении `my-daemon` основное приложение `my-app` и VIP не перезапускались и не мигрировали (fate-sharing устранён).
  - При падении `my-app` стек `core-app-stack`, VIP и `daemon-svc` корректно мигрировали на `node2`.
  - База данных на `node1` сохранила статус Master.
- **FAIL**: Падение `my-daemon` уронило `my-app`, либо при падении `my-app` миграция зависла.
