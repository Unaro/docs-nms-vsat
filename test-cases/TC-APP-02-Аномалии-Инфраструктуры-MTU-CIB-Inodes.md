# TC-APP-02: Аномалии инфраструктуры — MTU, дефицит диска CIB и Inodes

> **Примечание**: Данный тест-кейс относится к **Приложению: Специальные испытания на надежность (Day-2 Reliability Tests)** и проверяет реакцию на дефицит ресурсов ОС и сетевые аномалии.

## 1. Паспорт тест-кейса
- **Идентификатор**: `TC-APP-02`
- **Цель**: Проверить устойчивость кластера к системным отказам:
  1. Автодетекция и снижение размера MTU при Jumbo Frames Mismatch на Ring 0 (`net.ipv4.tcp_mtu_probing=1`).
  2. Защита диска CIB и проверка исчерпания Inodes (`df -i` > 95%).
  3. Устойчивость Corosync к паузам гипервизора при бэкапах (`token=3000ms`, `consensus=3600ms`).

---

## 2. Шаги выполнения и ожидаемые результаты

### Шаг 1. Проверка автодетекции MTU
**Действие:**
Проверить наличие sysctl-параметра:
```bash
sysctl net.ipv4.tcp_mtu_probing
# Ожидается: net.ipv4.tcp_mtu_probing = 1
```

### Шаг 2. Проверка контроля Inodes и диска
**Действие на `node1`:**
```bash
df -h "$PGDATA"
df -i "$PGDATA"
```
**Ожидаемый результат:**
- Анализатор `cluster-boot-analyzer.sh` блокирует запуск при превышении 95% занятых Inodes, предотвращая повреждение CIB и WAL.

### Шаг 3. Проверка параметров VM Stun
**Действие:**
```bash
corosync-cmapctl | grep "totem.token"
# Ожидается: totem.token (u32) = 3000
```
Паузы ВМ до 2.5 секунд при снапшотах не вызывают взаимный фенсинг узлов.
