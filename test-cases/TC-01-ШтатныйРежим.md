# TC-01: Проверка функционирования кластера в штатном режиме

## 1. Паспорт тест-кейса
- **Идентификатор**: `TC-01`
- **MMD-диаграмма**: [`mmd/ШтатныйРежим.mmd`](../mmd/ШтатныйРежим.mmd)
- **Цель**: Проверить корректность конфигурации и работоспособность всех компонентов кластера высокой доступности в нормальном сбалансированном состоянии (Node1 — Master, Node2 — Standby).
- **Объекты проверки**:
  - Транспорт Corosync knet по двум независимым кольцам (Ring 0, Ring 1).
  - Мониторинг маршрутизатора ресурсом `ping-gateway`.
  - Статус и репликация СУБД PostgreSQL 16 (`ocf:heartbeat:pgsqlms`).
  - Сокеты проверки роли БД `db-role-check.socket` (:9200).
  - Балансировщик HAProxy (:5000).
  - Размещение Виртуального IP (`CLUSTER_VIP` 192.168.1.100) и группы `app-stack`.
  - Запрет прямого автозапуска управляемых служб в systemd.

---

## 2. Предусловия
1. Скрипт `bootstrap-ha.sh` выполнен на `node1` и `node2`.
2. Кластер инициализирован командой `bootstrap-ha.sh --init-pcs` на `node1`.
3. Сеть настроена:
   - `node1`: Ring 0 = `10.0.0.1`, Ring 1 = `192.168.1.11`
   - `node2`: Ring 0 = `10.0.0.2`, Ring 1 = `192.168.1.12`
   - Маршрутизатор `192.168.1.1` доступен по ICMP.

---

## 3. Шаги выполнения и ожидаемые результаты

### Шаг 1. Проверка состояния межузловой связи Corosync knet
**Команда на обоих узлах:**
```bash
corosync-cfgtool -s
corosync-quorumtool -s
```
**Ожидаемый результат:**
- `corosync-cfgtool -s` показывает два активных линка:
  - `LINK ID 0`: `addr = 10.0.0.x`, статус `connected`, `enabled`.
  - `LINK ID 1`: `addr = 192.168.1.1x`, статус `connected`, `enabled`.
- `corosync-quorumtool -s` возвращает:
  - `Nodes: 2`
  - `Quorum: 2`
  - `Quorate: Yes`

### Шаг 2. Проверка статуса ресурсов Pacemaker
**Команда на `node1`:**
```bash
pcs status
```
**Ожидаемый результат:**
- Кластер в состоянии `Ok`.
- `Clone Set: ping-gateway-clone [ping-gateway]`: активен на `node1` и `node2` (значение `pingd=100`).
- `Clone Set: pgsql-clone [pgsql] (promotable)`:
  - `Promoted: node1` (Master).
  - `Unpromoted: node2` (Slave / Standby).
- `Resource Group: app-stack`:
  - `vip (ocf::heartbeat:IPaddr2)`: Started `node1`.
  - `haproxy-svc (systemd:haproxy)`: Started `node1`.
  - `app-svc (systemd:my-app)`: Started `node1`.
  - `daemon-svc (systemd:my-daemon)`: Started `node1`.
- Ошибки (Failed Resource Actions) отсутствуют.

### Шаг 3. Проверка сокета db-role-check (:9200)
**Команда на `node1`:**
```bash
curl -i http://127.0.0.1:9200/
```
**Ожидаемый результат на `node1`:**
```http
HTTP/1.1 200 OK
Content-Type: text/plain
Content-Length: 6

Master
```

**Команда на `node2`:**
```bash
curl -i http://127.0.0.1:9200/
```
**Ожидаемый результат на `node2`:**
```http
HTTP/1.1 503 Service Unavailable
Content-Type: text/plain
Content-Length: 5

Slave
```

### Шаг 4. Проверка балансировщика HAProxy и маршрутизации запросов
**Команда на `node1`:**
```bash
echo "show stat" | socat stdio /run/haproxy/admin.sock 2>/dev/null || true
psql -h 127.0.0.1 -p 5000 -U haproxy_check -d postgres -c "SELECT inet_server_addr(), pg_is_in_recovery();"
```
**Ожидаемый результат:**
- Подключение к локальному порту 5000 завершается успехом.
- Запрос возвращает IP-адрес текущего узла и `pg_is_in_recovery = f`.
- Бэкенд `node1_db` в статусе `UP`, бэкенд `node2_db` в статусе `DOWN` (из-за HTTP 503).

### Шаг 5. Проверка потоковой репликации PostgreSQL
**Команда на `node1`:**
```bash
sudo -u postgres psql -x -c "SELECT client_addr, state, sync_state, sync_priority FROM pg_stat_replication;"
```
**Ожидаемый результат:**
- Присутствует активная сессия репликации от `10.0.0.2` (по Ring 0).
- Поле `state` равно `streaming`.

### Шаг 6. Проверка блокировки прямого автозапуска в systemd
**Команда на обоих узлах:**
```bash
systemctl is-enabled postgresql haproxy my-app my-daemon
```
**Ожидаемый результат:**
- Все 4 сервиса имеют статус `disabled`, что исключает неконтролируемый старт в обход Pacemaker.

---

## 4. Критерии успешности (Pass/Fail)
- **PASS**: Все шаги 1–6 вернули в точности ожидаемые результаты.
- **FAIL**: Хотя бы один линк Corosync неактивен, сокет :9200 отдаёт неверный код ответа, сервисы запущены вне Pacemaker или репликация нарушена.
