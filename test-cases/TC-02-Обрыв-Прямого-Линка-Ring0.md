# TC-02: Обрыв прямого линка (Ring 0)

## 1. Паспорт тест-кейса
- **Идентификатор**: `TC-02`
- **MMD-диаграмма**: [`mmd/ШтатныйРежим.mmd`](../mmd/ШтатныйРежим.mmd)
- **Цель**: Проверить устойчивость кластера к аппаратному обрыву основного интерконнекта прямого кабеля (Ring 0), бесшовное переключение транспорта Corosync Knet на резервное кольцо (Ring 1) через сеть маршрутизатора и отсутствие ложного Split-Brain.
- **Объекты проверки**:
  - Двухкольцевой транспорт Corosync Knet (Failover с Link 0 на Link 1).
  - Сохранение кворума (`Quorate: Yes`).
  - Неизменность размещения ресурсов: VIP, СУБД Master и сервисы остаются на `node1` без перезапуска.

---

## 2. Предусловия
1. Кластер находится в базовом состоянии (успешно пройден `TC-01`).
2. `node1` является активным Master, VIP `192.168.1.100` поднят на `node1`.
3. Прямой линк Ring 0 работает на интерфейсе `eth1` (`10.0.0.1` <-> `10.0.0.2`).

---

## 3. Шаги выполнения и ожидаемые результаты

### Шаг 1. Имитация обрыва кабеля Ring 0
**Команда на `node1`:**
```bash
ip link set dev eth1 down
```

---

### Шаг 2. Проверка состояния линков Corosync Knet
**Команда на `node1` и `node2`:**
```bash
corosync-cfgtool -s
```
**Ожидаемый результат:**
- `LINK ID 0` переходит в статус `FAULTY` (или `not connected`).
- `LINK ID 1` (сеть `192.168.1.0/24`) остается в статусе `connected`, `enabled`.
- Heartbeat-трафик кластера продолжает бесперебойно циркулировать через Ring 1.

---

### Шаг 3. Проверка стабильности ресурсов Pacemaker
**Команда на любом узле:**
```bash
pcs status
```
**Ожидаемый результат:**
- **Split-Brain не происходит**.
- Кворум сохранен (`2 nodes configured, 2 expected votes, 2 nodes active`).
- Ресурсы `vip`, `core-app-stack` и `daemon-svc` **не мигрируют** и продолжают работать на `node1` без рестарта.
- СУБД на `node1` сохраняет статус Master, а на `node2` — статус Slave.
- HAProxy при необходимости задействует резервные маршруты `backup` через Ring 1 (`node2_db_r1`).

---

## 4. Восстановление исходного состояния
```bash
# На node1 поднимаем интерфейс eth1:
ip link set dev eth1 up

# Проверяем возврат линка Ring 0 в строй:
corosync-cfgtool -s
# Ожидается: LINK ID 0 - connected, enabled
```

---

## 5. Что делать при отклонении
1. Если при падении `eth1` кластер потерял кворум:
   - Проверить сетевую доступность адресов Ring 1:
     ```bash
     ping -c 2 192.168.1.11
     ping -c 2 192.168.1.12
     ```
   - Проверить конфигурацию `/etc/corosync/corosync.conf` на обоих узлах: убедиться, что директива `link linknumber=1` настроена на сетевые адреса маршрутизатора и порт 5406 открыт в файрволе.
2. Сбросить ошибки Knet:
   ```bash
   corosync-cfgtool -R
   ```
