# TC-08: Плановое корректное выключение кластера (Graceful Shutdown) и холодный старт

## 1. Паспорт тест-кейса
- **Идентификатор**: `TC-08`
- **MMD-диаграмма**: [`mmd/ПлановоеВыключениеКластера.mmd`](../mmd/ПлановоеВыключениеКластера.mmd)
- **Цель**: Проверить работу механизма перехвата штатной остановки узлов сервисом `cluster-shutdown-marker.service` и скриптом `cluster-mark-shutdown.sh`:
  1. Фиксация роли выключаемого узла (Master или Slave) в зависимости от количества оставшихся участников.
  2. Создание файла-маркера `/var/lib/cluster-state/graceful_shutdown`.
  3. Корректная остановка СУБД и кластера.
  4. Распознавание сценария `COLD_START` анализатором `cluster-boot-analyzer.sh` при последующем включении с коротким таймаутом (180 сек вместо 900 сек).
- **Объекты проверки**:
  - `cluster-shutdown-marker.service` и `/usr/local/sbin/cluster-mark-shutdown.sh`.
  - Запись маркера `graceful_shutdown` и его однократное считывание с мгновенным удалением.
  - Корректность определения сценария `MODE=COLD_START` vs `MODE=CRASH_RECOVERY`.

---

## 2. Предусловия
1. Кластер находится в штатном режиме (`node1` — Master, `node2` — Standby).
2. На обоих узлах активен сервис `cluster-shutdown-marker.service`:
   ```bash
   systemctl is-active cluster-shutdown-marker.service
   ```
   (Должен возвращать `active`).

---

## 3. Шаги выполнения и ожидаемые результаты

### Шаг 1. Плановое выключение резервного узла (node2)
**Команда на `node2`:**
```bash
systemctl stop pacemaker
```
**Ожидаемый результат на `node2`:**
1. Перед остановкой Pacemaker срабатывает `ExecStop` сервиса `cluster-shutdown-marker`:
   - Скрипт определяет: узел был `SLAVE`.
   - Создаётся файл `/var/lib/cluster-state/graceful_shutdown`:
     ```ini
     SHUTDOWN_TYPE=GRACEFUL
     LAST_KNOWN_ROLE=SLAVE
     TIMESTAMP=...
     ```
2. Pacemaker и PostgreSQL штатно останавливаются.

### Шаг 2. Плановое выключение мастера (node1)
**Команда на `node1`:**
```bash
systemctl stop pacemaker
```
**Ожидаемый результат на `node1`:**
1. Срабатывает `ExecStop` сервиса `cluster-shutdown-marker`.
2. Скрипт анализирует состояние:
   - `AM_I_MASTER="yes"`
   - `ONLINE_NODES_COUNT=1` (так как `node2` уже был остановлен).
   - `FINAL_ROLE="MASTER"`.
3. Создаётся файл `/var/lib/cluster-state/graceful_shutdown`:
   ```ini
   SHUTDOWN_TYPE=GRACEFUL
   LAST_KNOWN_ROLE=MASTER
   TIMESTAMP=...
   ```
4. В журнале фиксируется:
   `cluster-state: Штатная остановка (node1). Живых узлов: 1. Записана роль: MASTER`
5. PostgreSQL останавливается корректно (в заголовке `pg_controldata` статус: `shut down`).

### Шаг 3. Проверка последующего холодного старта node1
**Команда на `node1`:**
```bash
systemctl start cluster-boot-analyzer.service
```
**Ожидаемый результат:**
1. Скрипт `/usr/local/sbin/cluster-boot-analyzer.sh`:
   - Обнаруживает маркер `/var/lib/cluster-state/graceful_shutdown`.
   - Считывает `SAVED_ROLE=MASTER`.
   - **Мгновенно удаляет маркер с диска** (`rm -f /var/lib/cluster-state/graceful_shutdown`).
   - Проверяет `pg_controldata`: статус `shut down`.
2. В `/run/cluster_boot_mode` формируется:
   ```ini
   MODE=COLD_START
   LAST_ROLE=MASTER
   UNBLOCK_TIMEOUT_SEC=180
   ```
3. В системный журнал пишется:
   `cluster-precheck: Диски исправны. СЦЕНАРИЙ: Плановый холодный старт (таймаут 180 сек).`
4. Проверка удаления маркера:
   `test ! -f /var/lib/cluster-state/graceful_shutdown` -> успешно (файла нет).

### Шаг 4. Проверка ускоренной разблокировки в одиночном режиме
**Действие:**
Запустить Pacemaker на `node1` при выключенном `node2`.
**Ожидаемый результат:**
- По таймеру запускается `cluster-degraded-unblock.sh`.
- Время ожидания составляет всего **180 секунд** (3 минуты), а не 900 секунд (15 минут), так как выключение было штатным и безопасным.
- По истечении 180 секунд кворум разблокируется (`pcs quorum unblock --yes`), и сервис запускается на `node1`.

---

## 4. Критерии успешности (Pass/Fail)
- **PASS**: Роли перед выключением зафиксированы безошибочно (`node2=SLAVE`, `node1=MASTER`); маркер штатного выключения прочитан и удалён; режим определен как `COLD_START` с таймаутом 180 секунд; разблокировка произошла втрое быстрее аварийного таймаута.
- **FAIL**: Маркер не создался, роль мастера не распознана, маркер не удалился после чтения (риск ложного повторного использования), либо таймаут остался аварийным.
