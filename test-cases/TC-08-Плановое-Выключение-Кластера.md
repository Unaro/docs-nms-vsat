# TC-08: Плановое корректное выключение кластера (Graceful Shutdown) и холодный старт

## 1. Паспорт тест-кейса
- **Идентификатор**: `TC-08`
- **MMD-диаграмма**: [`mmd/ПлановоеВыключениеКластера.mmd`](../mmd/ПлановоеВыключениеКластера.mmd)
- **Цель**: Проверить работу механизма перехвата штатной остановки узлов сервисом `cluster-shutdown-marker.service` и скриптом `cluster-mark-shutdown.sh` (v2.0):
  1. Корректная фиксация роли Master даже при **одновременном/параллельном выключении обоих узлов** (защита от записи SLAVE на обеих нодах).
  2. Проверка наличия `standby.signal` для точного распознавания роли Standby/Master.
  3. Создание файла-маркера `/var/lib/cluster-state/graceful_shutdown`.
  4. Корректная остановка СУБД и кластера.
  5. Распознавание сценария `COLD_START` анализатором `cluster-boot-analyzer.sh` при последующем включении с коротким таймаутом (180 сек вместо 900 сек).
- **Объекты проверки**:
  - `cluster-shutdown-marker.service` и `/usr/local/sbin/cluster-mark-shutdown.sh` (v2.0).
  - Защита от параллельного shutdown обеих нод.
  - Запись маркера `graceful_shutdown` и его однократное считывание с мгновенным удалением.
  - Корректность определения сценария `MODE=COLD_START` vs `MODE=CRASH_RECOVERY`.

---

## 2. Предусловия
1. Кластер находится в штатном режиме (`node1` — Master, `node2` — Standby).
2. На обоих узлах активен сервис `cluster-shutdown-marker.service`:
   ```bash
   systemctl is-active cluster-shutdown-marker.service
   ```
   (Должен возвращать `active`).

---

## 3. Шаги выполнения и ожидаемые результаты

### Шаг 1. Тестирование параллельного выключения обоих узлов
**Действие:**
Имитировать одновременную остановку кластера на обоих серверах (например, через параллельное выполнение `systemctl stop pacemaker` на `node1` и `node2`):
```bash
# На node1 и node2 одновременно:
systemctl stop pacemaker
```

**Ожидаемый результат на `node1` (Master):**
1. Срабатывает `ExecStop` сервиса `cluster-shutdown-marker`.
2. Скрипт `cluster-mark-shutdown.sh`:
   - Находит узел в строке `Promoted:` crm_mon.
   - Записывает роль `MASTER` по умолчанию:
     `FINAL_ROLE="MASTER"`
   - Создаёт файл `/var/lib/cluster-state/graceful_shutdown`:
     ```ini
     SHUTDOWN_TYPE=GRACEFUL
     LAST_KNOWN_ROLE=MASTER
     TIMESTAMP=...
     ```
3. В журнале:
   `cluster-state: Штатная остановка (node1). Записана роль: MASTER`

**Ожидаемый результат на `node2` (Standby):**
1. Скрипт проверяет наличие `${PGDATA}/standby.signal`.
2. Поскольку файл `standby.signal` присутствует (узел остался репликой):
   `FINAL_ROLE="SLAVE"`
3. В маркер `/var/lib/cluster-state/graceful_shutdown` записывается:
   `LAST_KNOWN_ROLE=SLAVE`

### Шаг 2. Проверка последующего холодного старта node1
**Команда на `node1`:**
```bash
systemctl start cluster-boot-analyzer.service
```
**Ожидаемый результат:**
1. Скрипт `/usr/local/sbin/cluster-boot-analyzer.sh`:
   - Обнаруживает маркер `/var/lib/cluster-state/graceful_shutdown`.
   - Считывает `SAVED_ROLE=MASTER` (роль мастера сохранилась, несмотря на параллельный shutdown соседа!).
   - **Мгновенно удаляет маркер с диска** (`rm -f /var/lib/cluster-state/graceful_shutdown`).
   - Проверяет `pg_controldata`: статус `shut down`.
2. В `/run/cluster_boot_mode` формируется:
   ```ini
   MODE=COLD_START
   LAST_ROLE=MASTER
   UNBLOCK_TIMEOUT_SEC=180
   ```
3. В системный журнал пишется:
   `cluster-precheck: Диски исправны. СЦЕНАРИЙ: Плановый холодный старт (таймаут 180 сек).`
4. Проверка удаления маркера:
   `test ! -f /var/lib/cluster-state/graceful_shutdown` -> успешно (файла нет).

### Шаг 3. Проверка ускоренной разблокировки в одиночном режиме
**Действие:**
Запустить Pacemaker на `node1` при выключенном `node2`.
**Ожидаемый результат:**
- По таймеру запускается `cluster-degraded-unblock.sh`.
- Время ожидания составляет всего **180 секунд** (3 минуты), а не 900 секунд (15 минут), так как выключение было штатным и безопасным.
- По истечении 180 секунд кворум разблокируется (`pcs quorum unblock --yes`), и сервис запускается на `node1`.

---

## 4. Критерии успешности (Pass/Fail)
- **PASS**: Роли перед выключением зафиксированы безошибочно даже при одновременном останове (`node2=SLAVE`, `node1=MASTER`); маркер штатного выключения прочитан и удалён; режим определен как `COLD_START` с таймаутом 180 секунд; разблокировка произошла втрое быстрее аварийного таймаута.
- **FAIL**: Маркер не создался, роль мастера потеряна (записался SLAVE на обеих нодах), маркер не удалился после чтения, либо таймаут остался аварийным.
