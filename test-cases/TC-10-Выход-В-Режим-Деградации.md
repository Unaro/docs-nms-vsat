# TC-10: Выход в режим деградации (Старт бывшего Master в одиночку)

## 1. Паспорт тест-кейса
- **Идентификатор**: `TC-10`
- **MMD-диаграмма**: [`mmd/ВосстановлениеПослеПаденияМастерРезерв.mmd`](../mmd/ВосстановлениеПослеПаденияМастерРезерв.mmd)
- **Цель**: Проверить алгоритм аварийного вывода кластера в рабочий режим деградации при включении только одного узла (бывшего Master), если второй сервер физически сгорел или недоступен, снятие блокировки кворума (`pcs quorum unblock`) и запуск всех сервисов в одиночку.
- **Объекты проверки**:
  - Таймер `cluster-degraded-unblock.timer` и служба `cluster-degraded-unblock.service`.
  - Скрипт `/usr/local/sbin/cluster-degraded-unblock.sh`.
  - Проверка 4 предохранителей (связь с роутером, молчание соседа, отсутствие чужого VIP, статус СУБД `in production`).
  - Команда `pcs quorum unblock --yes`.

---

## 2. Предусловия
1. Кластер работал, `node1` был активным Master.
2. Оба узла выключены (или `node2` физически отключен от сети и питания).
3. Шлюз `192.168.1.1` доступен с `node1`.
4. Для сокращения времени теста в `/etc/default/ha-cluster` можно установить тестовый таймаут:
   ```bash
   sed -i 's/CRASH_TIMEOUT_SEC="900"/CRASH_TIMEOUT_SEC="20"/' /etc/default/ha-cluster
   sed -i 's/COLD_START_TIMEOUT_SEC="180"/COLD_START_TIMEOUT_SEC="20"/' /etc/default/ha-cluster
   ```

---

## 3. Шаги выполнения и ожидаемые результаты

### Шаг 1. Запуск только Сервера 1
**Действие:**
Включить питание **только `node1`**. Сервер `node2` остается полностью выключенным.

---

### Шаг 2. Контроль первоначальной блокировки Pacemaker
**Команда на `node1` сразу после загрузки:**
```bash
pcs status
```
**Ожидаемый результат:**
- `node2: OFFLINE`.
- Кворум отсутствует (`Quorate: No`), ресурсы стоят в состоянии `Stopped`.
- Таймер `cluster-degraded-unblock.timer` запущен и ведет обратный отсчет:
  ```bash
  systemctl list-timers cluster-degraded-unblock.timer
  ```

---

### Шаг 3. Контроль отработки сторожевого скрипта деградации
**Команда на `node1` после истечения таймаута:**
```bash
journalctl -u cluster-degraded-unblock.service -n 30 --no-pager
```
**Ожидаемый результат:**
- Сторож проверяет:
  1. Шлюз `192.168.1.1` доступен (`ROUTER_OK=yes`).
  2. Сосед молчит по ICMP и TCP (порты 9200, 5432, 22).
  3. `CLUSTER_VIP` не занят в локальной сети.
  4. Статус локальной БД по `pg_controldata` равен `in production`.
- Сторож фиксирует: `АВАРИЙНЫЙ СТАРТ: Локальная БД была Master. Активация режима деградации!`
- Выполняется команда `pcs quorum unblock --yes`.

---

### Шаг 4. Контроль запуска ресурсов
**Команда на `node1`:**
```bash
pcs status
```
**Ожидаемый результат:**
- Кворум принудительно разблокирован.
- СУБД промоутирована в `Master` (`Promoted: node1`).
- Ресурсы `vip`, `core-app-stack` и `daemon-svc` переходят в статус `Started` на `node1`.
- Сервер успешно обслуживает клиентов в одиночку!

---

## 4. Восстановление исходного состояния
```bash
# Вернуть боевые таймауты в /etc/default/ha-cluster:
sed -i 's/CRASH_TIMEOUT_SEC="20"/CRASH_TIMEOUT_SEC="900"/' /etc/default/ha-cluster
sed -i 's/COLD_START_TIMEOUT_SEC="20"/COLD_START_TIMEOUT_SEC="180"/' /etc/default/ha-cluster
```

---

## 5. Что делать при отклонении
1. Если по истечении таймаута кворум не разблокировался:
   - Проверить статус таймера и сервиса:
     ```bash
     systemctl status cluster-degraded-unblock.service
     ```
   - Проверить лог предохранителей: `journalctl -t cluster-watchdog -n 30 --no-pager`.
2. Если предохранитель отклонил старт из-за роутера:
   - Проверить пинг маршрутизатора `ping -c 2 192.168.1.1` и настройки `ROUTER_IPS`.
