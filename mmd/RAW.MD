# Реестр MMD-диаграмм HA-кластера (Pacemaker + PostgreSQL 16 + HAProxy)

Диаграммы отражают поведение и сценарии отказоустойчивости, реализованные в скрипте развертывания `bootstrap-ha.sh`.

| Файл диаграммы | Описание сценария | Ключевые компоненты |
|---|---|---|
| [ШтатныйРежим.mmd](./ШтатныйРежим.mmd) | Нормальное функционирование двухузлового кластера | Corosync knet (Ring0/Ring1), ping-gateway к маршрутизатору Eltex, опрос сокета `db-role-check.socket` (:9200), проксирование HAProxy (:5000), потоковая репликация WAL |
| [ПадениеБД1.mmd](./ПадениеБД1.mmd) | Отказ процесса СУБД на Master-узле | Детектирование через сокет :9200, сброс TCP-сессий HAProxy (`shutdown-sessions`), demote старого мастера, promote Standby через `pgsqlms`, миграция VIP и группы `app-stack` |
| [ПадениеApp1.mmd](./ПадениеApp1.mmd) | Отказ приложения `my-app` / демона `my-daemon` | Pacemaker мониторинг systemd, остановка `app-stack`, перенос VIP на узел 2, сохранение СУБД1 в роли Master, маршрутизация HAProxy2 через Ring 0 (интерконнект) на СУБД1 |
| [ПадениеApp1БД1.mmd](./ПадениеApp1БД1.mmd) | Полный отказ Сервера 1 (Node Crash / Double Failure) | Потеря связности по обоим кольцам Corosync, проверка ping-gateway на роутер Eltex, аварийный promote СУБД2, подъем VIP и app-stack на Сервере 2, работа в деградированном режиме |
| [ХолодныйСтартМастераРезерваПослеПадения.mmd](./ХолодныйСтартМастераРезерваПослеПадения.mmd) | Одновременный холодный старт обоих серверов после блэкаута | Предстартовые проверки `cluster-boot-analyzer.sh` (RW-тест, свободное место, pg_controldata), knet handshake двух колец, сравнение LSN/таймлайнов, запуск ресурсов |
| [ВосстановлениеПослеПаденияМастер.mmd](./ВосстановлениеПослеПаденияМастер.mmd) | Возврат ранее упавшего Master-узла в строй (Rejoin) | Проверки диска, Rejoin в Corosync, сохранение текущего мастера (`resource-stickiness=100`, без паразитного failback), rewind и ввод вернувшегося узла как Standby |
| [ВосстановлениеПослеПаденияМастерРезерв.mmd](./ВосстановлениеПослеПаденияМастерРезерв.mmd) | Холодный/аварийный старт одиночного узла без соседа (Деградация) | Таймер деградации `cluster-degraded-unblock.timer`, предохранитель сетевого арбитража (роутер и молчание соседа), предохранитель роли (`in production`), `pcs quorum unblock` |
| [ПлановоеВыключениеКластера.mmd](./ПлановоеВыключениеКластера.mmd) | Корректная плановая остановка серверов (Graceful Shutdown) | Сервис `cluster-shutdown-marker.service` (ExecStop), скрипт `cluster-mark-shutdown.sh`, фиксация роли последнего живого узла в `graceful_shutdown` |
